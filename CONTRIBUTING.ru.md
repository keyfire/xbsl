# Как дорабатывать xbsl

[English](CONTRIBUTING.md) · **Русский**

Спасибо за вклад. Ниже – минимум, чтобы добавить правило или обновить данные.

## Окружение

Требуется Python 3.10+. Данные о языке в репозиторий не входят – сначала сгенерируйте их из
своего дистрибутива 1С:Элемент (иначе линтер и часть тестов работать не будут):

```sh
python tools/extract.py --dist "<каталог дистрибутива>"     # все наборы данных

pip install -e ".[dev]"     # линтер + pytest + PyYAML
pytest                      # тесты (без данных зависящие от них пропускаются)
python -m xbsl <путь>   # прогон на исходниках
```

### Проверка в редакторе до релиза

Расширению VS Code не нужна переустановка пакета, чтобы показать правку движка вживую:
настройка `xbsl.lsp.command` указывает на `tools/lsp-dev.cmd`, и обертка запускает LSP-сервер
из этого клона (PYTHONPATH старше site-packages, поэтому клон побеждает установленный пакет
из любого каталога). После правки настройки перезагрузите окно – статус-бар покажет версию
движка из клона; уберите настройку и перезагрузите окно, чтобы вернуться к установленному
пакету. Интерпретатору нужны extras `[lsp]` и `[morph]`.

Подкоманды CLI из клона: `python -m xbsl` разбирает только режим проверки (подкоманду примет
за путь и отлинтует 0 файлов); используйте
`python -c "from xbsl.cli import main; main()" list-rules`.

### Какой именно xbsl сейчас работает

`python -m xbsl` из каталога клона кладёт рабочий каталог первым в `sys.path`, и исходники
МОЛЧА подменяют установленное колесо – проба тогда то падает, то нет, в зависимости от того,
откуда запущена, а дефект выглядит плавающим. Провенанс проверять явно, а не предполагать:

```sh
python -c "import xbsl.lexer as L; print(L.__file__)"
```

## Как добавить правило

1. Создайте модуль в `xbsl/rules/` (или дополните существующий).
2. Объявите функцию-правило и повесьте декоратор:

   ```python
   from xbsl.diagnostics import Diagnostic, Severity
   from xbsl.engine import SourceFile, rule

   @rule("группа/имя", "Короткий заголовок", "B", severity=Severity.WARNING)
   def моё_правило(source: SourceFile):
       if source.kind != "xbsl":
           return
       # ... вернуть/выдать Diagnostic(path, line, col, rule_id, severity, message)
   ```

   - `тир`: `A` структура/YAML, `B` текст/конвенции, `C` код, `D` семантика.
   - `scope="project"` – для кросс-файловых правил; тогда функция принимает `list[SourceFile]`.
   - `enabled_by_default=False` – если правило шумит на легаси (включается через `--select`).
   - Позиции строка/колонка – 1-индексированные. Для позиций используйте `xbsl.lexer.linemap`.

3. Подключите модуль в `xbsl/rules/__init__.py` (импорт регистрирует правило).
4. **Главное правило проекта:** прогоните на исходниках реального проекта и добейтесь **нуля ложных
   срабатываний**. Если правило массово срабатывает на существующем коде – делайте его `info` и
   выключенным по умолчанию, а не заставляйте всех править легаси.
5. Добавьте тест в `tests/` (образцы – в `tests/test_rules.py`).
6. Обновите сопутствующие метаданные тем же изменением: строку в таблицах `docs/RULES.md` и
   `docs/RULES.ru.md` (id, severity, умолчание, область, однострочное описание, ссылка на
   доки), счётчик правил там же и в обоих README, запись в
   `editors/vscode/src/ruleDocs.ts` – если за правилом стоит раздел документации платформы,
   счётчики уровней в описаниях групп (`editors/vscode/package.nls.json` и `.ru.json`), а для
   новой группы – ещё и настройку `xbsl.groups.<группа>` в `editors/vscode/package.json`.
   Всё перечисленное сверяется с реестром в `tests/test_metadata_sync.py`, так что забытое
   место видно сразу, а не при выпуске расширения.
7. **Если правило судит ИМЯ – заведите ему посев паритета**, см. ниже.

Лексер и данные о языке/типах извлечены из самой платформы (грамматика Xtext/ANTLR и доки
дистрибутива), а не выдуманы – держитесь этого принципа: сверяйтесь с первоисточником.

### Паритет двух написаний: правило сеют, а не считают его находки

Идентификаторы Элемента двуязычны, а таблицы, по которым судят правила, извлечены из
документации, существующей только по-русски. Правило, сверяющее текст исходника с такой
таблицей, читает переведённый проект по словарю, в котором этого проекта нет: оно пропускает
настоящие дефекты либо сообщает о том, что компилятор принимает. Лечится выводом английского
написания из словарей платформы (`xbsl/terms.py`, `xbsl/uischema.py`); рукописное второе
написание – не лечение: догадка не совпадает ни с чем и продолжает молча ни с чем не совпадать.

Замер ЛИНТОМ переведённого проекта со сверкой счётчиков находит только те правила, у которых
счёт сдвинулся. Он слеп к правилу, которое не срабатывает ни на одной стороне, – всё равно,
сломано ли оно или в проекте просто нет такой конструкции. Поэтому проверка сеет свой случай
сама:

```
python tools/parity_seed.py                    # все посевы
python tools/parity_seed.py --rule группа/имя  # одно правило
python tools/parity_seed.py --uncovered        # правила, за которые не отвечает ни один посев
```

Посев – это маленькое русское дерево и вердикт, который правило ему должно: находка или
тишина. Английский близнец берётся не из второй заготовки, а из собственного переводчика
инструментария, поэтому проверяется то самое написание, которое инструментарий действительно
порождает. Вердикт называет виноватую сторону и её промах (`en-misses`, `en-invents` и то же
для `ru-`): таблица без английского написания заставляет правило пропускать, а без русского
прочтения – выдумывать, и лечится это по-разному. Посев, переставший сеять свой случай, даёт
`stale`, а не проходит молча. Весь каталог гоняет `tests/test_parity_seed.py`, так что посевы
проверяются на каждом прогоне тестов, а не только когда об инструменте вспомнили.

Дыру, которую сегодня не закрыть, всё равно стоит посеять: укажите посеву причину через
`known=`, и он даст `known (...)` вместо провала. Удалить посев значило бы удалить
свидетельство, и следующий читатель открыл бы то же самое заново. Отметка – не место
прятать поломку: как только такой посев начнёт сходиться, он даст `fixed!` и уронит прогон –
это и есть знак, что отметку пора снять.

## Данные под новую версию Элемента

Данные версионированы в `xbsl/data/element/<версия>/`. Чтобы добавить новую версию,
возьмите её дистрибутив и запустите экстракторы – версия определится сама:

```sh
python tools/extract.py --dist "<каталог дистрибутива>"     # все наборы данных
```

Вендорные файлы дистрибутива не коммитятся (кэш в `.refs/`) – только производные JSON.
