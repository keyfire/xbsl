# XBSL

[English](https://github.com/keyfire/xbsl/blob/main/README.md) · **Русский**

**Документация: [docs.keyfire.ru/xbsl](https://docs.keyfire.ru/xbsl/ru/)**

![CI](https://github.com/keyfire/xbsl/actions/workflows/ci.yml/badge.svg)

Инструментарий XBSL для 1С:Элемент: линтер с автоисправлениями, LSP-сервер, индекс проекта,
поиск по документации платформы, создание метаданных, перевод исходников на английские написания
и MCP-сервер для ИИ-агентов. Плюс расширение VS Code на том же движке. Работает он по парам
файлов: `Имя.yaml` описывает элемент, `Имя.xbsl` держит код. И отвечает раньше, чем серверная
компиляция при деплое.

> До версии 0.16 проект назывался **xbsl-lint**, пакет `xbsllint`. Старые команды, импорты,
> переменные окружения и группы entry points продолжают работать как псевдонимы.

> Проект не аффилирован с фирмой "1С". "1С:Элемент", "1С:Фреш" и другие – товарные знаки их
> правообладателей. Данные о языке генерируются из вашего собственного дистрибутива. См. [NOTICE](https://github.com/keyfire/xbsl/blob/main/NOTICE).

Заметки о разработке и новости – в Telegram-канале [1С × ИИ: инженерный цех](https://t.me/ceh_1c_ai).

## Зачем

Внешних инструментов у платформы 1С:Элемент нет. Код проверяет только серверная компиляция при
деплое: она медленная и ничего не знает о соглашениях проекта. xbsl отвечает сразу и на вашей
машине, ловит то, что компилятор не проверяет вовсе, и берёт на себя механику метаданных –
создание объектов, реквизитов и форм.

## Как это устроено

Движок один, поверхностей четыре. Ядро читает пары `Имя.yaml` и `Имя.xbsl`, а записывает их
обратно тот код, который создаёт метаданные. CLI, LSP-сервер, MCP-сервер и веб-панель – тонкие
адаптеры над этим ядром, поэтому правила, данные и шаблоны у всех четверых одни:

![Ядро движка (линтер, автоисправления, индекс проекта, поиск по документации) и создание метаданных читают и пишут исходники проекта; закрытый плагин добавляет языковые данные Элемента и свои правила через точки расширения; CLI, LSP-сервер (VS Code), MCP-сервер (ИИ-агенты) и веб-панель – поверхности над одним ядром](https://raw.githubusercontent.com/keyfire/xbsl/main/images/how-it-works.ru.png)

## Быстрый старт

**Шаг 1 – установка.**

```sh
pip install xbsl              # или из клона репозитория: pip install -e .
```

**Шаг 2 – сгенерировать данные о языке.** Линтер судит по таблицам из **вашего** дистрибутива
1С:Элемент: ключевые слова, каталог типов stdlib, метамодель конфигурации, термины, индекс
документации, схема компонентов. В репозиторий эти таблицы не входят:

```sh
xbsl extract --dist "<каталог дистрибутива 1С:Элемент>"
```

Команда запускает все экстракторы разом. Из клона то же самое делает `python tools/extract.py`,
а подмножество шагов выбирает ключ `--only`. Версию платформы команда определяет сама и кладёт
данные в `xbsl/data/element/`, каталог перечислен в `.gitignore`. Где лежат данные и как
поставлять их закрытым пакетом, написано в
[руководстве](https://github.com/keyfire/xbsl/blob/main/docs/start.ru.md#данные-о-языке).

**Шаг 3 – запуск.**

```sh
xbsl путь/к/исходникам        # или: python -m xbsl путь/к/исходникам
xbsl data-diff                # что изменилось в платформе между двумя версиями данных
xbsl translate исходники      # перевод проекта на английские написания (словарь проекта)
xbsl self-update              # обновление до последней версии с PyPI, безопасно при занятых exe
```

Главные ключи: `--list-rules`, `--fix`, `--select`/`--enable`/`--ignore`,
`--baseline`/`--write-baseline`, `--format text|json|codeclimate`, `--lang ru|en`. Полный
справочник ключей, редакторские режимы `--stdin`/`--index`, нативные пакеты mypyc и устройство
`self-update` – в [руководстве](https://github.com/keyfire/xbsl/blob/main/docs/linting.ru.md#ключи-cli).

## Что умеет

**Правила.** 194 правила базового набора, в четырёх тирах. **A** – структура и схема yaml.
**B** – текст и типографика. **C** – структура кода: блоки, скобки, неиспользуемые переменные,
соглашения `style/`. **D** – семантика по данным платформы и самому проекту: каждая типовая
позиция в коде и yaml, значения перечислений, таблицы `Запрос{...}`, межфайловая
согласованность, типы подключённых библиотек `.xlib`. Полный перечень с уровнями и ссылками на
документацию – [docs/RULES.ru.md](https://github.com/keyfire/xbsl/blob/main/docs/RULES.ru.md).
На месте его печатает `xbsl --list-rules`. Что именно проверяет тир D, разобрано в
[руководстве](https://github.com/keyfire/xbsl/blob/main/docs/linting.ru.md#правила-подробно).

**Автоисправления.** `--fix` чинит прямо в файлах механические находки: хвостовые пробелы,
символы типографики, смешанные переводы строк. Всё, что требует суждения, он не трогает.

**Список принятых замечаний.** Правило включают на старом коде, не разгребая его весь сразу:
текущие находки один раз замораживают, а спрашивают только с нового кода. Тот же файл хранит
точечные исключения с причинами.
[Подробнее](https://github.com/keyfire/xbsl/blob/main/docs/linting.ru.md#список-принятых-замечаний-старый-долг-и-исключения-с-причиной).

**Создание метаданных.** Объекты, реквизиты, маршруты и формы заводятся без ручного yaml:
33 вида элементов, формы с настоящим наполнением, контекстное переименование `rename-object`,
правка прав доступа. Одни и те же операции доступны из CLI, MCP и LSP:

```sh
xbsl new-object vendor/Приложение/Основное Справочник Товары
xbsl add-field vendor/Приложение/Основное/Товары.yaml реквизит Цвет --type Строка
xbsl add-form . --name Товары            # формы объекта и списка + регистрация
xbsl rename-object . Товары Номенклатура # файлы + ссылки по всему проекту
```

Платформа двуязычна: вид элемента – это и `Справочник`, и `Catalog`. Инструмент принимает любое
написание, а пары берёт из словаря терминов, извлечённого из вашего дистрибутива. Виды секций у
`add-field` пока пишутся только на языке проекта. Перечень видов, которые можно создать,
покажет `xbsl new-object --help`.

Все подкоманды с ключами – в
[руководстве](https://github.com/keyfire/xbsl/blob/main/docs/scaffolding.ru.md#создание-метаданных).

**Редакторы.** [Расширение VS Code](https://github.com/keyfire/xbsl/blob/main/editors/vscode/README.ru.md)
([Marketplace](https://marketplace.visualstudio.com/items?itemName=keyfire.xbsl),
[Open VSX](https://open-vsx.org/extension/keyfire/xbsl)) даёт подсветку синтаксиса, живую и
проектную диагностику, переходы к определению и автодополнение, конструктор форм, дерево
метаданных и кнопку деплоя. Работает оно на `xbsl-lsp`. Это Language Server, и поднять его
может любой редактор с поддержкой LSP
([подробнее](https://github.com/keyfire/xbsl/blob/main/docs/servers.ru.md#lsp-сервер)).

**Шаблоны кода.** Набираете `есл`, жмёте Ctrl+Space и получаете конструкцию целиком, с точками
ввода. Встроенных шаблонов 51, и каждый разобран парсером самого линтера, так что вставить
некомпилируемый код нельзя. Свои шаблоны лежат в `.xbsl-templates.json`, а управляет ими панель
в VS Code. Механизм и формат файла повторяют 1С:EDT.
[Подробнее](https://github.com/keyfire/xbsl/blob/main/docs/scaffolding.ru.md#шаблоны-кода).

**Поиск по документации.** `tools/extract_docs.py` превращает справку Элемента из дистрибутива
в локальную полнотекстовую базу `docs.sqlite`; по ней ищут API `xbsl.docs` и инструменты MCP.
[Подробнее](https://github.com/keyfire/xbsl/blob/main/docs/platform-data.ru.md#поиск-по-документации).

**MCP-сервер.** `claude mcp add xbsl -- xbsl-mcp` даёт агенту проверку исходников, поиск по
документации, `type_members` и все операции создания метаданных инструментами `meta_*`. Агент
создаёт объект и в том же ответе получает проверку записанных файлов.
[Подробнее](https://github.com/keyfire/xbsl/blob/main/docs/servers.ru.md#mcp-сервер).

**Веб-интерфейс.** `xbsl-web` – локальная страница над тем же движком: настройки правил,
фильтры, темы. [Подробнее](https://github.com/keyfire/xbsl/blob/main/docs/servers.ru.md#веб-интерфейс).

**CI.** Ненулевой код возврата бывает только при находках уровня error, поэтому `xbsl` встаёт
в конвейер как есть. `--format codeclimate` питает виджет GitLab Code Quality. Готовые задачи
конвейера для GitHub Actions и GitLab CI собраны в
[руководстве](https://github.com/keyfire/xbsl/blob/main/docs/linting.ru.md#использование-в-ci).

**Расширение движка.** Точки расширения (entry points) позволяют закрытому пакету добавить
правила, поставлять языковые данные и переопределять уровни. Отводить для этого собственную
копию линтера не нужно. Все плагины разом отключает `XBSL_NO_PLUGINS=1`.
[Подробнее](https://github.com/keyfire/xbsl/blob/main/docs/servers.ru.md#расширение-свои-правила-данные-и-уровни).

Язык вывода (RU/EN), версии данных Элемента и порядок поиска корня данных описаны там же, в
[руководстве](https://github.com/keyfire/xbsl/blob/main/docs/start.ru.md#язык-вывода).
