Панель документации расширения содержит справку 1С:Элемент в редакторе. Контейнер
**Документация (1С:Элемент)** расположен на панели действий. Справочник формируется из
дистрибутива 1С:Элемента, соответствует его версии и доступен без сети.

## Что внутри

- **Дерево "Содержание"** – оглавление, собранное вручную и совпадающее с сайтом: руководство
  разработчика, руководство администратора, типы языка (`Стд`, `Стд::Коллекции` → `Массив`,
  ...), свойства элементов проекта и компонентов интерфейса (ключи их описаний в yaml), схема
  процесса интеграции, язык запросов и глоссарий. Разделы внутри страницы (`Иерархия типа`,
  `Примеры`, `Литералы`) вложены в ее узел, поэтому клик ведет сразу к нужному месту.
- **Страница** открывается вкладкой редактора сбоку и **не забирает фокус**. На ней код,
  таблицы и картинки статьи, кнопка **Копировать** у примеров и ссылка **Первоисточник** на ту
  же страницу сайта. Внутренние ссылки ведут к другим страницам в этой же вкладке, а дерево
  "Содержание" выделяет открытую страницу.
- **Поиск** доступен по кнопке в шапке дерева и по команде *XBSL: поиск по документации*.
  Полнотекстовый поиск охватывает справочник и оба руководства. Выбор результата открывает
  страницу.

## Как сюда попадают

Панель можно открыть из следующих мест расширения:

| Откуда | Что делает |
| --- | --- |
| Наведение на имя в `.xbsl` | подсказка показывает описание и ссылку **Документация**, клик по ней открывает страницу. Над членом типа показан блок самого члена: сигнатура и что делает вызов. Ссылка тогда открывает страницу на этом члене |
| Контекстное меню редактора, *XBSL: документация по символу* | страница типа под курсором. У члена это страница, прокрученная к нему. Если имя объявлено несколькими типами, предлагается выбор из этих типов |
| **Палитра** конструктора, *Открыть документацию* | страница компонента, который вы собираетесь вставить. Краткое описание видно и в подсказке элемента палитры |
| Дерево "Содержание" и поиск | обычная навигация по справочнику |

Член описан там, где его объявили. `Массив.Размер` открывает страницу предка, который его
объявил: у наследника о члене нет ни слова. Когда одно имя объявлено несколькими неродственными
типами, на выбор предлагаются эти типы, и строкой под каждым идет блок члена с его страницы. У
остальных имен без своей страницы кандидаты **ранжируются по приемнику перед точкой**:
Для `Задание.Настроить` страницы запланированного задания располагаются выше одноименного
раздела руководства.

Для имени, объявленного в проекте, подсказка содержит карточку проекта: например, метод, его сигнатуру и
файл. Индекс проекта определяет объекты, методы модулей, компоненты форм, табличные части и
значения перечислений, поэтому документация одноименного встроенного члена в карточку не
добавляется. Например, для метода проекта `Записать` не подставляется справка
одноименного встроенного метода. При этом панель предлагает поиск по имени в
документации 1С:Элемента.

## Что нужно

- **Режим LSP** (`pip install "xbsl[lsp]"`): сервер хранит базу документации, а расширение
  запрашивает и показывает ее содержимое.
- **Данные документации**, собранные из вашего дистрибутива 1С:Элемент – см.
  [Данные о языке](/ru/start#данные-о-языке).

Без данных панель сообщает, что документация недоступна. Остальные возможности расширения
продолжают работать.

## Для скриптов и агентов

Тот же справочник доступен вне редактора:

- **MCP** – `docs_search` для полнотекстового поиска, `docs_page` для статьи по
  идентификатору и `docs_symbol` для документации типа или его члена. Своей страницы у члена
  нет, поэтому он отвечает своим блоком со страницы типа. Оба страничных инструмента умеют
  отвечать кратко (`brief` – краткое описание и имена разделов) и одним разделом (`section`),
  когда статья целиком больше, чем нужно вопросу. Именно так ИИ-агент сверяет API 1С:Элемента,
  не выходя в сеть.
- **LSP** – запросы `xbsl/docsAvailable`, `xbsl/docsSearch`, `xbsl/docsPage`, `xbsl/docsTree`,
  `xbsl/docsForSymbol` и `xbsl/hoverDoc`. Над ними любой редактор с поддержкой LSP может собрать
  свою панель. Последние два отвечают на член так же, как `docs_symbol`: страницей объявившего
  типа, именем члена и идентификатором его заголовка.

`docs_symbol` также находит члены, создаваемые 1С:Элементом у компонентов интерфейса проекта:
`СобственнаяМодифицированность`, `РассчитаннаяМодифицированность` и `ОтслеживатьИзменениеДанных`.
Они описаны в статье о типах компонентов. Ответ содержит страницу, блок члена и его `section`.
