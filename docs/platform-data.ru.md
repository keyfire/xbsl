Семантические правила, автодополнение и панель документации читают данные, извлечённые из дистрибутива. Эта страница – про сами данные: что ещё из них собирается и как разводятся версии.

## Поиск по документации

`tools/extract_docs.py` извлекает справку Элемента из дистрибутива – из `.car` сервера с IDE – в
базу `docs.sqlite` рядом с данными языка. В базу попадают страницы stdlib с очищенным HTML: тип,
его методы, свойства и параметры. Рядом ложится полнотекстовый индекс SQLite FTS5 из стандартной
библиотеки и канонические ссылки на первоисточник вида `https://1cmycloud.com/docs/help/...` –
адрес берётся из `sitemap.xml` дистрибутива. Картинки страниц сохраняются тут же. Справка 1С под
охраной авторского права, поэтому базу не кладут в пакет: её генерируют из своего дистрибутива,
как и данные языка.

```sh
python tools/extract_docs.py --dist "$ELEMENT_DIST"
```

Базу `docs.sqlite` читает API `xbsl.docs`: `search`, `page`, `tree`, `for_symbol`, `asset`, а
также чистые `sections` и `summarize` над HTML страницы. Если базы нет, поиск просто пуст. На
этом API работают инструменты MCP, а в дальнейшем будет работать и панель справки в расширении
VS Code.

## Версии Элемента

Данные версионированы по версии платформы:

```
xbsl/data/element/
    index.json            # { available: [...], default: "<версия>" }
    <версия>/{language.json, stdlib.json, metamodel.json}
```

Версию выбирают ключом `--element-version`, переменной окружения `XBSL_ELEMENT_VERSION` или
полем `default` из индекса. Что доступно, показывает `--version`. Новая версия появляется от
повторного запуска `xbsl extract` с новым `--dist`. Версией по умолчанию индекс делает самую
новую, а повторная генерация старой версии умолчание не двигает.

Что изменилось в платформе между двумя версиями данных, показывает `xbsl data-diff [старая]
[новая]`. Без аргументов он сравнивает версию по умолчанию с ближайшей более старой. В отчёт
идут типы и члены stdlib, свойства метамодели, компоненты и их свойства, термины и страницы
документации. `--format md` пишет полный отчёт в Markdown, `--format json` – машинный вид, а в
текстовом виде каждый список ограничен ключом `--limit`. Члены типов сравниваются с развёрнутым
наследованием, и изменение поднимается к корню иерархии: добавка в базовом типе не повторяется у
каждого наследника.

Сам корень данных ищется по порядку: ключ `--data-dir`, переменная окружения `XBSL_DATA_DIR`,
корень из установленной точки расширения `xbsl.data`, затем `xbsl/data/element` внутри пакета.
